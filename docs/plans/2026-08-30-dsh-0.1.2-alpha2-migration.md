# @huanlin/dsh-plugin-android-use · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 生成日期：2026-08-30 · 依据：tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be) 差异摘要 + 对 alpha2 源码的只读核查（`git -C D:/Projects/deepseek-harness/dsh show/diff/grep`，未修改 dsh/ 任何文件）。

## 结论

**✅ 直接可升。** 本插件消费的全部 dsh 面（host：`tools` 服务、`defineTool`、`attachments`/`llm` 服务；client：`slots` 服务、keyed slot `tool.call.toolview`、`uiConversation.imageUrl`；DSSH 模块加载器契约）在 alpha2 中 API 与签名零变化；alpha2 最受关注的破坏点 `connectionGeneration → hostInfo` 注入 hook 改名只影响读取该 hook 的 client 插件，本插件从未读取它。升级仅需「更新 dsh 源码 checkout → 重建 lib/ → 重启验证」，插件源码无需任何改动。

## 迁移步骤

**核心结论：插件源码（src/、cordis.patch.yml、package.json 结构）无需任何改动。** 需要的只有宿主侧升级与产物重建验证。

1. **升级 DSH 源码 checkout 到 alpha.2**（人类执行，按 AGENTS.md「更新 DSH 源码 checkout」SOP）：
   - 对 `~/.dsh/source/current` 与 dev clone 各自 `git pull --ff-only origin master`（或 checkout 至 `dsh-v0.1.2-alpha.2` 之后的 master）；
   - `pnpm install --prefer-offline` + `pnpm run build`（前台长 timeout，勿塞 bgProcess）；验证 `apps/cli/lib/bin.js` 与 `packages/bundle/web-app/lib/index.js` 存在。
2. **刷新插件类型检查用的 junction**（若 `node_modules/@deepseek-ai/*` 已存在则无需重建——junction 指向 `C:\Users\Administrator\.dsh\source\current`，源码升级后内容自动变为 alpha2；仅当 junction 缺失时按 README「开发」节重新创建）。
3. **重建 lib/ 并跑三件套**（workdir = `D:/Projects/deepseek-harness/dsh-plugin-android-use`）：
   ```powershell
   pnpm run typecheck   # 对 alpha2 声明做 --noEmit 检查（预期零错误：所用 API 全部未变）
   pnpm test            # vitest run，132 用例
   pnpm run build       # tsc + tsdown → lib/index.js + lib/client.js
   ```
   说明：现有 `lib/` 是对 alpha1 预构建的，而本插件 client bundle 运行时只 require react（`@deepseek-ai/*` 引用全为纯类型），host 侧 API 又未变，故**即使不重建，旧 lib/ 也与 alpha2 兼容**；重建属验证性动作 + 保持产物与源码同步。Windows 上若 `build` 的 clean 步骤报错，先 `Remove-Item lib -Recurse -Force` 再跑（README/SOP 已知坑）。
4. **profile 端生效**：
   - `link:` 引用（README 安装方式 A）：重建 `lib/` 后 profile 的 `node_modules/@huanlin/dsh-plugin-android-use/lib/` 直接可见，**无需** `dsh plugin add/update`；
   - `github:`/npm 引用（对外分发用户）：`dsh plugin --profile web update @huanlin/dsh-plugin-android-use`。
5. **重启 `dsh web` 进程 + 浏览器硬刷新（Ctrl+Shift+R）**。
6. **对外发布（走 huanlinoto 发布 SOP，本仓库后续版本流程）**：预构建策略下 `pnpm run build` → `git add lib/` → commit（建议顺带 bump version，如 `0.1.1`，并可选将 peerDependencies 对齐 `^0.1.2-alpha.2`）→ push；npm 侧 `npm pack --dry-run` 核对 `files` 清单后 `pnpm publish`。**不要**提交本机 junction/link 路径补丁到上游。
7. **无需改动的清单**（明说）：`src/index.ts`、`src/client/index.ts`、`src/client/TapCard.tsx`、`src/client/ScreenshotCard.tsx`、`src/tools/*`、`src/route.ts`、`cordis.patch.yml`、`tsdown.config.ts`（`window.__ModuleLoader__.load` 包裹契约 alpha2 不变）、`files`/`peerDependenciesMeta`/`dsh.client.inject` 结构。

## 升级后验证清单

> 以下每步都要求：`dsh web` 已重启（宿主跑在 alpha.2）**且**浏览器已 `Ctrl+Shift+R` 硬刷新。

1. **加载健康**：dsh web 启动无 stderr 的 `Failed to load plugins` / `missed the module table` / `Cannot find package '@deepseek-ai/…'`（任一出现即插件与 alpha2 失配，需回查本文对照表）。
2. **插件注册**：GUI 设置 → 插件清单可见 `dsh-android-use`，配置项 `adbPath`（默认 `adb`）、`defaultSerial`、`inputTextMode` 三项齐全可编辑（settings schema 走 schemastery，alpha2 未变）。
3. **工具可用**：新开会话，让模型调用 `android_list_devices` → 应返回已连接设备 JSON；无设备时返回明确错误（不挂起）。
4. **感知双通道**：
   - `android_screenshot`：工具卡片出现（ScreenshotCard），UI 卡内截图正常显示（attachment → `uiConversation.imageUrl` 链路）；文本注记含 `Image emitted to model context: yes/no`，与当前模型路由的图像能力一致（本会话模型若支持图像输入应为 yes）。
   - `android_ui_dump`：返回交互节点列表，坐标为缩放后 image space。
5. **点击链路**：让模型依据 ui_dump 的 center 坐标调用 `android_tap` → TapCard 渲染 Pre-tap（带标记）与 Post-tap 两张对照截图；真机上确认点击落点正确。
6. **取消/失败路径**：拔掉设备后再调用任一工具 → 应返回基础设施失败 JSON（不卡死、不误报成功）；`exec.signal` 取消在途 adb 进程行为不变（C6 自检项）。
7. **回归对照**：同机同会话内连续 3+ 轮工具调用，确认 conversation 流中卡片顺序、运行态（Capturing… → completed/error 徽标）与 alpha1 时期一致。
8. （可选）若宿主端 Web 出现新的「连接恢复指示器」（alpha2 新增），确认其出现/消失不影响已渲染的 android 卡片。
