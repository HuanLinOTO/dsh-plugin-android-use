## 改动

### 1. RC1-01 cohort

- `package.json`：peerDependencies + devDependencies 的 `@deepseek-ai/dsh-*` 全部 `^0.1.5-rc.1`/`^0.1.5-rc.2` → `^0.1.7-rc.1`（`@deepseek-ai/cordis` 保持 `^4.0.1`）。
- `pnpm-workspace.yaml`（本机 dev 文件，.gitignore 排除）：`minimumReleaseAgeExclude` 旧 cohort 条目随 install 更新为 `0.1.7-rc.1`。
- 新增 devDependency `@deepseek-ai/dsh-sandbox@^0.1.7-rc.1`：`dsh-tools@0.1.7-rc.1` 在 `lib/index.js` 顶层静态 `import '@deepseek-ai/dsh-sandbox'`（其声明 peer），而本工程 `autoInstallPeers:false`，缺它则 `pnpm test` 整套解析失败（`Cannot find package '@deepseek-ai/dsh-sandbox'`）。仅 dev 环境需要；发布包不进 devDeps，运行期由宿主提供 dsh-tools 的 peer closure。
- 新增 peerDependency `@deepseek-ai/dsh-client-ui-chat@^0.1.7-rc.1`（`optional`）：`ToolCallViewProps.block` 的三阶段类型定义在 ui-chat（ui-tool 的 `contract/slots.ts` 从 `@deepseek-ai/dsh-client-ui-chat/client` 导入 `PreparingToolCall/StartedToolCall/ToolResultNode`）。缺失时 `skipLibCheck` 吞掉 `.d.ts` 报错、`props.block` 退化为 `any`，RC1-23 的破坏性变更不会被静态捕获。仅类型依赖，**不**加进 `dsh.client.inject`（运行期模块边不变）。

### 2. RC1-23 toolview 三阶段

`src/client/TapCard.tsx`、`src/client/ScreenshotCard.tsx`：

```tsx
export function TapCard(props: ToolCallViewProps) {
  if (props.phase === 'preparing') return /* 无参数的轻量行：data-state="preparing" */
  return <StartedTapCard {...props} />
}
function StartedTapCard({ phase, block, toolName, loadImage }: StartedToolCallViewProps) {
  const settled = phase === 'result' ? block : undefined
  const running = phase === 'start' ? block : undefined   // 仅 'start' 才有 argsRaw
  ...
}
```

- 先分支 `phase === 'preparing'`，其余委托 `StartedToolCallViewProps`（`Exclude<ToolCallViewProps, {phase:'preparing'}>`）。
- 弃用 `'kind' in block` 判别，改为 `phase` 判别，`argsRaw` 只在 `phase==='start'`（`StartedToolCall`）/`phase==='result'`（`ToolResultNode.call`）读取。
- `preparing` 行无参数、无截图（渲染 "Capturing…" 占位），不再访问不存在的 `RunningToolCall.argsRaw`。
- `loadImage` 仍为必需的 `MessageImageLoader`；`inspect` 本插件未用。
